# 全项目图谱化业务规则 Prompt

基于项目代码先建立 Graphify 图谱，再生成可追溯、非开发者可读的全量业务规则文档。

## 输入

- 项目根目录、可分析源码目录、用户关注的系统边界和已有文档。
- 可选：Graphify 已有图谱、允许使用的 LLM 语义提取配置、输出文件名与格式要求。

先列出：已知事实、信息缺口、冲突信息、可能过期项、范围外事项和最小假设。不得把密钥写进项目文件、文档、命令历史或日志。

## 你要做的事

1. 确认仓库/代码根，排除构建产物、依赖/vendor、生成代码；检查已有 Graphify 输出是否覆盖当前源码。
2. 先构建或刷新 Graphify 图谱，再执行 `query`、`path` 等查询定位入口、服务、实体、Mapper/SQL、任务、消息和外部客户端。
3. 回查源码、SQL/XML、配置与任务定义，确认每条业务规则；图谱只作为导航证据。
4. 生成一份项目本地 Markdown：模块地图、入口目录、实体/状态、数据与配置、端到端链路、模块规则、异常/运营链路、测试范围、待确认项和追溯索引。

## 执行规则

- 对每个模块说明：业务目标、触发、输入、决策、输出/副作用、异常、上下游链接和来源。
- 规则必须区分：资格过滤、排序/选择、运行时限额/去重/并发/回滚。
- 排序必须写明字段、方向、空值规则、并列行为和后置过滤；未被执行比较器/查询使用的字段不得称为排序依据。
- 对图谱的 INFERRED/语义关系标为“发现线索”，用源码确认后才写成事实。
- 同一模块的不同入口、异常或定时链路合并为同节分支。

## 最低覆盖清单

- [ ] 图谱范围、构建/查询命令、图规模和证据边界。
- [ ] 全量业务模块、入口和至少一条端到端链路。
- [ ] 核心实体、状态、配置、数据读写和外部系统边界。
- [ ] 每个模块至少一张规则表；复杂决策有 Mermaid 流程/状态图。
- [ ] 测试范围包含正常、边界、异常、状态、并发/幂等（适用时）、外部依赖和未执行项。
- [ ] 关键结论均有 `src/...:line` 或等价可定位来源。

## 输出

按顺序输出：范围与证据边界；系统地图；模块目录；实体/状态/数据关系；端到端链路；按模块合并的业务规则；排序与例外；测试范围和矩阵；需求待确认；代码追溯；验证记录。

## 质量要求

- 默认 Markdown、表格与 Mermaid；面向非开发者，解释业务含义而非堆叠类名。
- 不执行真实业务请求，不声称未运行的集成、数据库、调度或生产行为已通过。
- 无可用语义 LLM 时，退化为结构图谱+源码复核，并在证据边界写明。
- 提交前验证来源、章节、图表、密钥泄露和 Markdown 空白错误。
