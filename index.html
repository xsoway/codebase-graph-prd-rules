##它解决什么What it solves

两组互补的 AI 代理 Skill，把项目源码整理成供产品 / 运营 / QA 阅读的、可追溯的详细业务规则文档。

$ 图谱导航，源码确认Graph navigates, source confirms

图谱定位入口与候选链路，每条规则再逐一用真实源码、SQL/XML 与配置确认。INFERRED 图谱边只是线索，不是事实

The graph locates entries and call chains; every rule is then confirmed against source, SQL/XML and config.An INFERRED edge is a lead, never a fact

$ 三层规则Three-layer rules

资格过滤 → 候选排序 → 运行时控制，绝不混为一谈；排序写明字段、方向、null 规则与并列行为。

Qualification filter → candidate sorting → runtime control, never conflated; sorting states fields, direction, null rules, tie-breaks.

$ 只分析，不执行Analyze, never act

除非用户显式授权，拒绝调用真实下游服务、发送真实线索、改动数据或运行生产行为。

Refuses to call real downstream services, send real leads, mutate data, or run production behavior without explicit authorization.

$ 证据等级Evidence levels

EXTRACTED / INFERRED / 源码确认 分开报告，静态与运行行为清晰分离。

EXTRACTED vs INFERRED vs source-verified are reported separately; static vs runtime clearly distinguished.

##两个 SkillThe two skills

选择规则：一个明确边界的模块用 module-rules；无单模块边界的全项目扫描用 business-rules。

Choose: module-rules for one bounded module/feature; business-rules for a whole-project scan with no boundary.

##常见问题FAQ

该用哪个 Skill？Which skill should I use?
一个边界明确的模块用 codebase-graph-module-rules；无单模块边界的全项目扫描用 codebase-graph-business-rules。
Use codebase-graph-module-rules for one bounded module/feature; codebase-graph-business-rules for a whole-project scan.
需要 LLM 凭据吗？Do I need an LLM credential?
不需要。语义提取仅在显式提供凭据时执行；无凭据时退化为结构图谱 + 源码复核。
No. Semantic extraction runs only when you explicitly provide a credential; otherwise it falls back to structural graph + source review.
这些 Skill 会改我的代码吗？Do these skills modify my code?
不会。两者只分析和写文档；改动业务代码、数据或外部系统需另行显式授权。
No. Both analyze and write documents only; changing code/data/external systems requires separate explicit authorization.
能把规则导出 CSV/JSON 吗？Can I export rules to CSV/JSON?
可以，明确要求时在 Markdown 主稿之外附加导出。
Yes, on explicit request, in addition to the Markdown primary deliverable.
